# 교수님 발표용 NOVA 시연 시나리오 (3~5분)

## 프로젝트 목적
여러 AI 모델을 하나의 모바일 환경에서 사용하고, 단일 모델의 답변에서 벗어나 **각 모델을 서로 다른 역할의 전문가로 배정해 작업을 협업 처리**하는 멀티 AI 플랫폼을 구현한다.

## 개발에서 AI 활용
- 기획 및 요구사항 정리: 생성형 AI 활용
- SwiftUI 화면·아키텍처·서버 코드 작성 지원
- 오류 분석 및 테스트 코드 작성 지원
- AI의 제안은 개발 환경에서 실제 검증한다는 전제

## 실제 앱 내부 AI 기능
- GPT / Claude / Gemini 공식 API 연결(개별 계정 및 키 필요)
- 사진+텍스트 및 PDF 추출 텍스트 질의
- 3개 AI의 답변 생성 및 차이점 분석
- 다중 AI 토론(찬성/반대/반박)
- AI 팀의 각 역할별 순차 수행 및 최종 통합
- 프롬프트 개선

## 발표 흐름
**0:00~0:30** 홈 화면에서 앱 설명. "각 AI를 따로 사용하거나 팀으로 구성할 수 있습니다."

**0:30~1:15** AI Hub에서 모델 하나를 선택해 질문 전송. 지원 모델을 개별적으로 사용할 수 있다는 점 소개.

**1:15~2:00** AI Lab의 Compare에 동일 질문을 입력하고 3개의 결과 비교. 비교가 끝나면 Fusion 버튼으로 공통점/충돌점을 정리.

**2:00~3:30** AI Team에서 '앱 개발 드림팀' 열기. "기획자→디자이너→개발자→검토자" 역할을 순차 실행하고 생성된 보고서 확인.

**3:30~4:10** Debate Arena에서 간단한 토론 주제로 AI가 주장/반박을 주고받는 모습 소개.

**4:10~4:40** Vault에서 결과를 다시 열고 내보내기. 결론: 앱을 만드는 과정에서도 AI를 사용했고, 앱 내부에서도 다중 AI가 협업한다.

> **중요:** 실제 API 연결 전에는 모든 답변이 **DEMO** 예시 문구입니다. 교수님 발표에서 실제 AI를 시연하려면 서버 API 연결을 먼저 확인하세요.

## 예상 질문 답변
**Q. 이게 단순한 챗봇과 뭐가 다른가요?**
A. GPT/Claude/Gemini 선택 외에도 여러 모델의 응답 비교, 역할 기반 작업 분배, 이전 결과를 다음 에이전트에 전달하는 협업 워크플로우를 제공합니다.

**Q. 에이전트는 무엇을 자율적으로 하나요?**
A. 사용자 요청을 계획 단계에서 분해하고, 정해진 팀 역할 순서에 따라 후속 프롬프트를 구성하고, 결과를 통합합니다. 모든 역할이 외부 웹을 자동 검색하거나 시스템을 직접 제어하는 수준은 아닙니다.

**Q. 모델별 답이 다르면 어느 쪽이 맞나요?**
A. 모델의 답변 공통점과 차이점을 구분하고 미확인 주장을 표시하며, 정확성 판단에는 외부 근거가 추가로 필요합니다.

**Q. 기술 스택은 무엇인가요?**
A. SwiftUI, Apple Speech, PhotosPicker, PDFKit, SwiftData 대신 로컬 Codable JSON 저장, FastAPI, OpenAI/Anthropic/Gemini API, 역할 기반 오케스트레이션입니다.
